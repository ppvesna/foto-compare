# Правила работы помощников

Эти правила действуют для AI-помощников и разработчиков, вносящих изменения в `foto-compare`.

## Взаимодействие с владельцем

- Идея, вопрос, схема или описание проблемы не являются командой менять код.
- Изменения выполняются после явной команды: «делай», «исправь», «начинай» или равнозначного запроса.
- «Обсудим» или «вопрос» означает только анализ без правок.
- Коммит и пуш выполняются только по явной команде.

## Git

- Рабочая ветка: `feature/oleg-work`.
- Рабочее дерево может содержать изменения владельца. Их нельзя откатывать, перезаписывать или добавлять в коммит без согласования.
- Файлы для коммита добавляются явным списком, а не `git add -A`, если дерево смешанное.
- Деструктивные `git reset --hard` и `git checkout --` без явного согласия запрещены.

## Изменения

- Снача прочитать код и тесты затрагиваемого модуля.
- Сохранять текущее поведение и форматы локальных данных.
- Не переписывать рабочий код ради Architecture v2.
- Мигрировать по одному модулю и проверять сборку после каждого шага.
- Новые функции писать в Architecture v2, если модуль уже определён.
- `CompareScreen` пока является legacy-контуром. Его уменьшают постепенно, но не переписывают целиком.

## Проверка

- Форматировать изменённые Dart-файлы.
- Запускать точечный `dart analyze`.
- Запускать релевантные тесты, если среда разрешает.
- Для web-изменений собирать `flutter build web --debug`.
- Честно сообщать о тестах, которые не удалось запустить.
