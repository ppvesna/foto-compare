# План: переработка процесса сравнения (следующий этап)

Согласовано в обсуждении 2026-06-13. Реализация — по шагам, только после
команды «Делай».

## Новая структура страниц

Основной сценарий (95% случаев): **эталон = цифровой файл, образец = фото с камеры**.

1. **Эталон**
   - Основной путь: загрузка файла.
   - Доп. опции (редкие случаи): фото с камеры, слияние нескольких фото
     (текущий блок «Эталон 2» / «🔀 Объединить»).

2. **Образец**
   - Основной путь: фото с камеры (с перспективной коррекцией, как сейчас).
   - Доп. опции: файл, слияние нескольких фото.

3. **Точки** (новая страница, **обязательный шаг**)
   - Расстановка якорных точек на эталоне и образце.
   - Зум перед постановкой точки (сейчас в `AnchorPointScreen` зума нет).
   - Кнопки точного зума/сдвига для совмещения по масштабу
     (вместо/в дополнение к `InteractiveViewer` мышью).
   - **Без расставленных точек кнопка «Сравнить» недоступна** —
     показывать подсказку, почему это важно.
   - Можно вернуться на эту страницу повторно (передобрать точки) без
     повторной загрузки эталона/образца.

4. **Сравнение**
   - Запуск `_runCompare()` с использованием точек для выравнивания
     (масштаб/наложение/кроп по точкам — вместо текущего грубого
     `_fitCrop` в `compare_service.dart`).

5. **Результат** — как сейчас.

«История» — отдельно, вне основного потока 1→5.

## Известные проблемы, требующие проверки/исправления

- **`databaseFactory not initialized`** при сравнении (после коммита
  `f90ed7d`, добавившего `_saveCheckResult()`): `LocalDatabase` использует
  `sqflite`, который не поддерживает веб без `sqflite_common_ffi_web`.
  На вебе `_saveCheckResult()` сейчас ломает весь `_runCompare()`.
- **Разница в разрешении эталона и образца остаётся** даже после фикса
  `perspectiveCorrect` для обоих изображений (коммит `a311053`) —
  требуется дополнительная диагностика.
- **Отправка результата сравнения в Supabase** — после фикса
  `databaseFactory` нужно проверить, что запись реально появляется в
  `check_results` через `SyncService`.
